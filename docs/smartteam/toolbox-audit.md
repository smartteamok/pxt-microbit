# SmartTEAM toolbox audit

This audit compares the current toolbox implementation with `docs/smartteam/toolbox-spec.md`.

## Files changed

- `docs/smartteam/toolbox-spec.md`
  - Added the complete SmartTEAM toolbox specification and color palette.
- `docs/smartteam/toolbox-audit.md`
  - Added this audit.
- `editor/extension.tsx`
  - Uses `toolboxOptions` to rename and color MakeCode built-in toolbox categories:
    - `functions` -> `Funciones`
    - `loops` -> `Control`
    - `logic` -> `Lógica`
    - `maths` -> `Matemáticas`
    - `variables` -> `Variables`
    - `text` -> `Texto`
    - `arrays` -> `Variables`
  - Starts the new curated-toolbox strategy by defining an explicit `Control` block whitelist.
- `libs/radio/targetoverrides.ts`
  - Renames the radio category to `Comunicación` while keeping the native radio color.
- Native metadata only, no implementation changes:
  - `libs/core/basic.cpp`: native Basic blocks are placed under `Control`.
  - `libs/core/control.ts`: native Control advanced blocks are placed under `Control`, keeping native color.
  - `libs/core/input.cpp` and `libs/core/input.ts`: native Input blocks are placed under `Entradas`, keeping native color.
  - `libs/core/pins.cpp` and `libs/core/pins.ts`: native Pins blocks are placed under `Entradas`, keeping native color.
  - `libs/core/led.cpp` and `libs/core/led.ts`: native LED blocks are placed under `Pantallas`, keeping native color.
  - `libs/core/images.cpp`: native image blocks are placed under `Pantallas`, keeping native color.
  - `libs/core/music.ts` and `libs/core/soundexpressions.ts`: native music/sound blocks are placed under `Salidas`, keeping native color.
  - `libs/core/serial.ts` and `libs/core/console.ts`: native serial/console blocks are placed under `Comunicación`, keeping native colors.
- SmartTEAM package metadata:
  - `libs/smartteam-core/main.ts`: category color set to `#FF9800` and placed under `Control`.
  - `libs/smartteam-inputs/main.ts`: category color set to `#9C27B0`.
  - `libs/smartteam-outputs/main.ts`: category color set to `#F44336`.
  - `libs/smartteam-display/main.ts`: category color set to `#3F51B5`.
  - `libs/smartteam-motors/main.ts`: category color set to `#42A5F5`.

## Categories currently configured

- `Funciones` via MakeCode `functions` toolbox category.
- `Control` via MakeCode `loops` toolbox category plus native `basic` / `control` and `smartteam-core`.
- `Lógica` via MakeCode `logic`.
- `Matemáticas` via MakeCode `maths`.
- `Variables` via MakeCode `variables` and `arrays`.
- `Texto` via MakeCode `text`.
- `Comunicación` via native `radio`, with native `serial` and `console` placed into that namespace.
- `Entradas` via `smartteamInputs`, with native `input` and `pins` placed into that namespace.
- `Salidas` via `smartteamOutputs`, with native `music` and `soundexpressions` placed into that namespace.
- `Pantallas` via `smartteamDisplay`, with native `led` and `images` placed into that namespace.
- `Motores` via `smartteamMotors`.

## Native blocks reused

- Control flow and function blocks from MakeCode runtime categories.
- Native `basic.pause`, `basic.forever`, `basic.show*`, and related Basic blocks now surface through `Control` when included by PXT.
- Native button, gesture, logo, light, temperature, acceleration, compass, sound, and pin blocks through `Entradas`.
- Native radio, serial, and console blocks through `Comunicación`.
- Native LED matrix and image blocks through `Pantallas`.
- Native music/sound blocks through `Salidas`.

The product direction changed after this audit began: visible blocks should now use the SmartTEAM category color where possible. Native APIs may still be used internally through SmartTEAM wrappers.

## SmartTEAM custom blocks reused

- `smartteamCore.waitMs`, `onButtonPressed`, `onGesture`, `onLogoPressed`, `startStopwatch`, `stopwatch` -> `Control`.
- `smartteamCore.disableLedMatrix` and `enableLedMatrix` remain available to TypeScript but are hidden from the visible toolbox.
- `smartteamInputs.*` sensor/input blocks -> `Entradas`.
- `smartteamOutputs.*` LED/tone/buzzer blocks -> `Salidas`.
- `smartteamDisplay.*` LCD/RGB blocks -> `Pantallas`.
- `smartteamMotors.*` motor/servo/fan/robot blocks -> `Motores`.

SmartTEAM custom blocks use the category colors defined in `toolbox-spec.md`.

## Blocks that still do not fully match the spec

- The spec asks for a small whitelist of blocks per category. `Control` now starts using a strict whitelist; the remaining categories still need the same treatment.
- Some native blocks from `basic`, `input`, `pins`, `led`, `images`, `music`, `serial`, and `console` remain visible if PXT includes them in the toolbox flyout. They are functional and have only been relocated.
- `Funciones` is still MakeCode's native function editor category. Exact labels such as `Crear función con retorno` / `Si devuelve` are generated by PXT and may not exactly match the Spanish wording in the spec.
- `Matemáticas` currently uses native MakeCode math blocks. `Mapear` may appear as native `pins.map` if available in the Pins APIs, but it is not yet wrapped as a SmartTEAM math block.
- `Comunicación / Bluetooth` blocks listed in the spec (`Enviar por bluetooth...`, `Control del Robot`, `Joystick`, `Botón A`, `Botón B`) do not yet exist as SmartTEAM Bluetooth-specific blocks.
- `Comunicación` still uses native radio/serial exposure and needs a SmartTEAM wrapper/whitelist pass to get consistent category color.
- `Entradas / Externos` still lacks explicit SmartTEAM wrappers for `OBSTÁCULO` and a pin-parameterized external temperature block matching the spec wording exactly.
- `Derecha`, `Centro`, `Izquierda` are currently enum/dropdown values for line position, not separate standalone blocks.
- `Pantallas / Matriz 8x8` blocks are not implemented yet; current display support covers LCD and RGB strip plus native micro:bit LED/image blocks.
- `Motores / Movimiento robot` exists through generic move/stop controls, but exact wording and RM/LM pin labels are not yet identical to the spec.

## Blocks intentionally left visible and why

- Native MakeCode runtime blocks that are part of the default editor (for example function editor, variable editor, logic/math/text primitives) are temporarily left visible until each category gets an explicit SmartTEAM whitelist.
- Native micro:bit input, pins, LED, image, music, radio, serial, and console blocks are left visible for now because they preserve hardware functionality and compile behavior. Hiding individual native APIs would require a stricter toolbox whitelist or wrapper-only strategy.
- Generated files such as `libs/core/shims.d.ts` are not edited directly; `buildtarget` regenerates them from persistent `.cpp` / `.ts` sources.

## Risks and follow-up tasks

- Extend the strict toolbox whitelist strategy beyond `Control`.
- Add SmartTEAM wrappers for spec-only blocks that do not exist yet: Bluetooth message helpers, obstacle sensor, external temperature wording, 8x8 matrix display, and exact robot motor wording.
- Confirm whether `Variables` should include native Arrays/List blocks. The current configuration places arrays near Variables because PXT exposes arrays as a built-in toolbox category.
- Confirm physical hardware labels for RM/LM, IIC, RGB color order, obstacle sensor pinout, and whether external temperature belongs under `Digitales` or `Analógicas`.
- Re-run `npx pxt buildtarget --skip-core` after toolbox metadata changes so `built/target.json` and API info are regenerated.
